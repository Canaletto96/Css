CSS Урок 56. Организация CSS-файлов

1. Проблема: один огромный файл

В начале проекта — один style.css. Через месяц — 3000 строк. Найти что-то — боль. 

/* style.css (3000 строк) */
/* reset */
/* typography */
/* header */
/* nav */
/* cards */
/* forms */
/* footer */
/* ... */

Решение — разбить на несколько файлов по смыслу.

2. Один файл vs несколько

Один файл Несколько файлов
Простота Проще начать Сложнее
Найти код Сложно (3000 строк) Легко (по названию)
Команда Конфликты при merge Каждый в своём файле
Кеш Один файл Несколько файлов
Загрузка Один запрос Много запросов
Когда Маленькие проекты Средние и большие
Правило: до 500 строк — можно один файл. Больше — разбивать.

3. Как разбить CSS

Способ 1: по типу

css/ ├── reset.css ← сброс стилей ├── typography.css ← шрифты, заголовки ├── layout.css ← сетка, контейнеры ├── components.css ← кнопки, карточки └── utilities.css ← утилиты (.hidden, .mt-4)

Способ 2: по компонентам (BEM)

css/ ├── base.css ← reset, переменные ├── components/ │ ├── button.css │ ├── card.css │ ├── header.css │ └── footer.css └── pages/ ├── home.css └── about.css

Способ 3: по страницам

css/ ├── common.css ← общее для всех ├── home.css ← только главная ├── about.css ← только «О нас» └── contact.css ← только «Контакты»
Рекомендую: по компонентам (способ 2). Легче найти, что относится к кнопке, а что к карточке. Хорошо сочетается с BEM.

4. Как подключить несколько файлов

Способ 1: несколько <link>

<link rel="stylesheet" href="css/reset.css">
<link rel="stylesheet" href="css/typography.css">
<link rel="stylesheet" href="css/layout.css">
<link rel="stylesheet" href="css/components.css">
<link rel="stylesheet" href="css/utilities.css">

Способ 2: @import в одном файле

/* style.css */
@import url("reset.css");
@import url("typography.css");
@import url("layout.css");
@import url("components.css");
@import url("utilities.css");
<link rel="stylesheet" href="css/style.css">

5. <link> vs @import

<link> @import
Загрузка Параллельно Последовательно
Скорость Быстрее Медленнее
Где писать В HTML В CSS
Кеширование Обычное Обычное
Рекомендация Да Только для сборки
Не используй @import в продакшене!
  • Загружается последовательно — медленнее.
  • Нельзя распараллелить.
  • Сложнее отлаживать.
Используй <link> или сборщики (Webpack, Vite, Parcel).

6. Порядок подключения

Порядок важен — CSS каскадируется. Кто ниже — тот «перебивает». 

<!-- 1. Reset — первым -->
<link rel="stylesheet" href="css/reset.css">

<!-- 2. Base — переменные, шрифты -->
<link rel="stylesheet" href="css/base.css">

<!-- 3. Layout — сетка, контейнеры -->
<link rel="stylesheet" href="css/layout.css">

<!-- 4. Components — кнопки, карточки -->
<link rel="stylesheet" href="css/components.css">

<!-- 5. Pages — специфика страниц -->
<link rel="stylesheet" href="css/pages.css">

<!-- 6. Utilities — утилиты (последними) -->
<link rel="stylesheet" href="css/utilities.css">
Правило:
  1. Reset — первым (убирает стили браузера).
  2. Base — переменные, шрифты.
  3. Layout — сетка.
  4. Components — компоненты.
  5. Pages — специфика страниц.
  6. Utilities — последними (перебивают всё).

7. Пример структуры проекта

my-site/ ├── index.html ├── about.html ├── css/ │ ├── reset.css ← сброс │ ├── variables.css ← CSS-переменные │ ├── base.css ← body, шрифты │ ├── components/ │ │ ├── button.css │ │ ├── card.css │ │ ├── header.css │ │ └── footer.css │ ├── layout.css ← сетка │ └── utilities.css ← утилиты └── images/

8. Альтернатива: сборщики

В реальных проектах используют сборщики, которые объединяют все CSS в один файл автоматически.

Инструмент Что делает
ViteСовременный сборщик
WebpackМощный, сложный
ParcelПростой, без настройки
SassПрепроцессор + @import / @use
Как работает: в проекте — много файлов, но сборщик объединяет их в один bundle.css. Браузер грузит один файл — быстро.

9. Практика: разбей CSS

Возьми свой style.css и разбей на части:

  1. reset.css — *, body, img, input, button.
  2. variables.css — :root { --primary: ... }.
  3. base.css — body, h1–h6, p, a.
  4. components/button.css — .btn.
  5. components/card.css — .card.
  6. layout.css — .container, .grid.
  7. utilities.css — .hidden, .mt-4.

10. Частые ошибки

Ошибка Почему плохо
@import в продакшене Загружается последовательно — медленнее
Подключать utilities.css первым Утилиты должны быть последними (перебивают всё)
Один огромный файл Сложно найти, конфликты в команде
Слишком много файлов (20+) Много запросов — медленно
Забыть reset.css Стили браузера «мешают»
Перемешать компоненты и утилиты Сложно понять, что где

11. Что запомнить из урока

  • Один файл — для маленьких проектов (< 500 строк).
  • Несколько файлов — для больших.
  • Разбивать по компонентам — лучший способ.
  • Порядок подключения: reset → base → layout → components → pages → utilities.
  • <link> лучше @import — параллельная загрузка.
  • Сборщики (Vite, Webpack) — для реальных проектов.
  • Не 20+ файлов — много запросов.
  • Утилиты — последними (перебивают всё).
  • Reset — первым.
