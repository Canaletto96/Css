CSS Урок 5. Специфичность и каскад

1. Проблема: два правила — одно свойство

Что если два CSS-правила задают одно и то же свойство для одного элемента? 

p {
    color: red;
}

p {
    color: blue;
}

Какой цвет будет? Ответ — синий. Потому что каскад.

Каскад (cascading) — это набор правил, по которым браузер решает, какой стиль применить, если их несколько. Отсюда название CSS — Cascading Style Sheets.

2. Три уровня приоритета

Когда два стиля конфликтуют, браузер сравнивает их по трём критериям по порядку:

Уровень Критерий Кто побеждает
1 Важность Без !important < с !important
2 Специфичность Более конкретный селектор
3 Порядок Кто ниже в CSS — тот побеждает
Логика:
  1. Сначала — есть ли !important. Если да — побеждает он.
  2. Если у обоих нет — сравнить специфичность.
  3. Если специфичность равна — побеждает тот, что ниже в файле.

3. Специфичность — что это

Специфичность (specificity) — это «вес» селектора. Чем конкретнее селектор, тем он важнее.

Специфичность считается как четыре числа (a, b, c, d):

Компонент Что считается Вес
a !important 1 (или 0)
b #id 100
c .class, [attr], :pseudo-class 10
d тег, ::pseudo-element 1
Важно: числа не складываются как обычные. 11 классов не победят 1 id — потому что id и класс — разные «разряды». Это как «11 копеек < 1 рубль».

4. Примеры специфичности

Селектор Специфичность Пояснение
* (0, 0, 0, 0) Универсальный — вес 0
p (0, 0, 0, 1) Один тег
p span (0, 0, 0, 2) Два тега
.card (0, 0, 1, 0) Один класс
p.card (0, 0, 1, 1) Класс + тег
.card .title (0, 0, 2, 0) Два класса
#header (0, 1, 0, 0) Один id
#header .card (0, 1, 1, 0) id + класс
#header .card p (0, 1, 1, 1) id + класс + тег
a:hover (0, 0, 1, 1) Псевдокласс + тег
a::before (0, 0, 0, 2) Тег + псевдоэлемент
style="" (1, 0, 0, 0) Инлайн-стиль (как id, но выше)
!important ↑ всё Перебивает всё

5. Сравнение: кто победит

/* Специфичность: (0, 0, 0, 1) */
p {
    color: red;
}

/* Специфичность: (0, 0, 1, 0) — ВЫШЕ */
.card {
    color: blue;
}

Победит синий (класс специфичнее тега).

/* Специфичность: (0, 0, 1, 0) */
.card {
    color: blue;
}

/* Специфичность: (0, 1, 0, 0) — ВЫШЕ */
#header {
    color: green;
}

Победит зелёный (id специфичнее класса).

6. Порядок в CSS

Если специфичность равна, побеждает тот, что ниже в файле:

.order-test {
    color: red;
}

.order-test {
    color: blue;   /* ← это победит (ниже) */
}
Результат:

Этот текст — синий, потому что правило ниже.

Почему так: представь, что браузер читает CSS сверху вниз и «перезаписывает» стили. Кто ниже — тот записал последним.

Порядок подключения CSS

Порядок имеет значение и между файлами:

<!-- Сначала этот -->
<link rel="stylesheet" href="style.css">

<!-- Потом этот — перезапишет совпадающие -->
<link rel="stylesheet" href="override.css">

7. !important — ядерная кнопка

!important заставляет свойство игнорировать специфичность и порядок. 

p {
    color: red !important;
}

#header .card p {
    color: blue;
}

Победит красный, несмотря на то что #header .card p специфичнее.

Не используй !important без крайней необходимости!
  • Ломает каскад — ты не можешь переопределить стиль.
  • Через год ты сам не вспомнишь, зачем поставил.
  • Приходится ставить !important на !important — ад.
Когда можно:
  • Переопределяешь стили сторонней библиотеки (Bootstrap).
  • Пишешь утилитарный класс (например, .hidden { display: none !important; }).
  • Email-письма (там свои причуды).

8. Порядок применения стилей

Полный порядок (от низшего к высшему):

  1. Стили браузера (user agent) — встроенные.
  2. Стили пользователя — настройки в браузере (редко).
  3. Стили автора (твои) — обычные CSS.
  4. Стили автора с !important.
  5. Стили пользователя с !important — настройки доступности.
  6. Стили браузера с !important — крайне редко.
Для тебя важны пункты 3 и 4: твои обычные стили и твои !important. Всё остальное — редкость.

9. Практические примеры

Пример 1: класс vs тег

<p class="intro">Текст</p>

p { color: red; }         /* (0,0,0,1) */
.intro { color: blue; }   /* (0,0,1,0) — побеждает */

Результат: синий.

Пример 2: id vs 10 классов

<div id="header" class="a b c d e f g h i j">...</div>

#header { color: red; }      /* (0,1,0,0) */
.a.b.c.d.e.f.g.h.i.j { color: blue; }  /* (0,0,10,0) */

Результат: красный. Один id побеждает 10 классов.

Важно: 10 классов не равны 1 id. Это разные разряды. id всегда выше.

Пример 3: инлайн-стиль vs id

<p id="text" style="color: green;">Текст</p>

#text { color: red; }   /* (0,1,0,0) */
/* style="" имеет специфичность (1,0,0,0) — побеждает */

Результат: зелёный (инлайн-стиль).

Пример 4: !important vs всё

p { color: red !important; }
#header .card p { color: blue; }
p { color: green; }

Результат: красный. !important перебивает всё.

10. Как избежать «войн специфичности»

Проблема: если стили конфликтуют, ты начинаешь добавлять !important, потом ещё один — и код превращается в ад.

Правила:

  1. Используй классы, не id для стилей.
  2. Не углубляйся больше 2–3 уровней: .card .title, а не div > section > .card > .title.
  3. Один класс — одна ответственность (BEM).
  4. Не используй !important без причины.
  5. Порядок файлов: сначала reset, потом базовые, потом компоненты, потом утилиты.

11. Как проверить специфичность в DevTools

Открой F12 → Elements → выбери элемент. Справа — панель Styles.

Ты увидишь:

  • Применённые стили — обычным текстом.
  • Перебитые стили — зачёркнуты.
  • Откуда каждый стиль — файл и строка.

Это лучший способ понять, какой стиль победил и почему.

12. Частые ошибки

Ошибка Почему плохо
Использовать id для стилей Высокая специфичность — сложно переопределить
Ставить !important «на всякий случай» Ломает каскад, приходится ставить ещё один
Думать, что 10 классов = 1 id Нет. id всегда выше, это разные разряды
Использовать div > section > ul > li > a Слишком высокая специфичность, хрупко
Забывать про порядок файлов Стили могут «перебить» друг друга неожиданно
Не проверять в DevTools Гадание вместо фактов

13. Что запомнить из урока

  • Каскад — правила, по которым браузер решает, какой стиль применить.
  • Три критерия: !important → специфичность → порядок.
  • Специфичность считается как (id, классы, теги).
  • Специфичность: * = 0, тег = 1, класс = 10, id = 100.
  • 10 классов ≠ 1 id. id всегда выше.
  • Инлайн-стиль style="" — выше id, но ниже !important.
  • При равной специфичности побеждает тот, что ниже.
  • !important — крайняя мера. Не используй без причины.
  • DevTools — лучший способ понять, что победило.
  • Правило: используй классы, не углубляйся, не спамь !important.
